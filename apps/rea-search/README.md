# REA Search

파일 이름을 입력하는 즉시 찾아 주는 Windows용 검색 프로그램입니다. 필요할 때는 파일 **내용**에서 단어를 찾을 수도 있습니다.

## 실행

1. `REASearch.exe`를 내려받아 더블클릭합니다. 설치나 Python은 필요 없습니다.
2. "이 앱이 디바이스를 변경하도록 허용하시겠어요?" 창이 뜨면 **예**를 누릅니다. 관리자 권한이 있으면 NTFS 드라이브 전체를 몇십 초 안에 색인하고 이후 변경을 실시간으로 반영합니다. **아니요**를 누르면 폴더를 훑는 방식으로 동작하고 한 시간마다 다시 훑습니다.
3. 검색 창(Edge 또는 Chrome의 앱 창)이 열립니다. 콘솔 창은 없습니다.
4. 창을 닫아도 프로그램은 뒤에서 색인을 최신으로 유지합니다. exe를 다시 실행하면 즉시 창만 다시 열립니다. 완전히 끄려면 **설정 > 정보 > 프로그램 완전히 종료**를 누릅니다.

서명되지 않은 새 프로그램이라 Windows SmartScreen이 경고를 띄울 수 있습니다. **추가 정보 > 실행**을 누르면 됩니다.

옵션: `REASearch.exe D:\Projects` (이 폴더만 색인), `-no-admin` (관리자 권한 요청 안 함), `-port 39713` (화면 포트).
데이터 폴더: `%LOCALAPPDATA%\REASearch` (색인 캐시, 설정, `REASearch.log`).

## 화면과 기능

- **이름 검색**: 입력하는 즉시 결과. `Aa` 대소문자 구분, `경로` 전체 경로에서 찾기, `.*` 정규식.
- **왼쪽 필터**: 유형(문서·이미지·영상·음악·압축·코드·실행 파일·폴더, 개수 표시), 수정한 날짜(오늘, 7일, 30일, 올해, 1년 넘게 안 바뀐 파일, 직접 지정), 크기.
- **보기**: 검색 결과, 중복 파일 찾기(같은 이름과 같은 크기끼리 묶음), 최근 바뀐 파일(실시간 감시로 들어온 생성·수정·이름 변경·삭제).
- **정렬**: 열 머리글 클릭(이름, 경로, 크기, 날짜, 유형). 정렬과 필터는 위쪽 칩으로 보이고 X로 끕니다.
- **미리보기**: 텍스트는 앞부분과 일치한 줄, 이미지는 그림, 폴더는 들어 있는 항목.
- **저장한 검색, 최근 검색**, 결과 **CSV 내보내기**(Excel에서 한글이 깨지지 않게 저장).
- **우클릭 메뉴**: 열기, 폴더에서 보기, 경로·이름 복사, 같은 폴더에서 검색, 같은 확장자만 보기, 이 폴더 내용 검색, 내용 색인에 추가.
- **추가 폴더**(설정 > 검색할 폴더): 네트워크 공유(`\\서버\공유`)나 다른 드라이브를 추가합니다. 폴더마다 다시 훑는 간격(기본 1시간)을 정하고, 연결이 끊겨도 마지막 색인을 유지합니다.
- 단축키: `Ctrl+F` 이름 검색, `Ctrl+Shift+F` 내용 검색, `Enter` 열기, `Ctrl+Enter` 폴더에서 보기, `Space` 미리보기, `Ctrl+C` 경로 복사.

## 이름 검색 문법

| 입력 | 의미 |
|---|---|
| `foo bar` | 이름에 foo **와** bar가 모두 포함 |
| `foo \| bar` | foo **또는** bar |
| `!foo` | foo 제외 |
| `*.mp4`, `d?g.*` | 와일드카드 (이름 전체와 일치) |
| `json\ decoder` | `\`나 `/`가 들어간 단어는 전체 경로에서 찾기 |
| `ext:jpg;png` | 확장자 필터 |
| `file:` / `folder:` | 파일만 / 폴더만 |
| `"two words"` | 공백 포함 단어 |

## 파일 내용 검색 (원할 때만)

평소에는 이름만 찾습니다. 위쪽 **내용 검색** 버튼(`Ctrl+Shift+F`)을 누르면 내용 검색 줄이 열립니다. 찾을 범위는 **지금 이름 검색과 필터에 걸린 파일**입니다. 예를 들어 이름 칸에 `ext:docx;hwpx`, 날짜 필터 "최근 30일"을 걸고 내용 칸에 단어를 넣으면 그 파일들만 읽습니다.

| 입력 | 의미 |
|---|---|
| `회의 예산` | 두 단어가 **모두** 있는 파일 (AND) |
| `회의 \| 예산` 또는 `회의 OR 예산` | 둘 중 **하나**라도 (OR) |
| `회의 !취소` 또는 `회의 -취소` | 회의는 있고 취소는 **없는** 파일 (NOT) |
| `"분기 실적"` | 정확히 이 구문 |

옵션: `Aa` 대소문자 구분, `단어` 단어 단위로만 일치, `.*` 정규식. 결과마다 일치한 줄이 강조되어 나오고, 미리보기에서 전체 일치 줄을 볼 수 있습니다.

읽는 형식: 텍스트·코드 파일(UTF-8, UTF-16, EUC-KR/CP949), Word(docx), Excel(xlsx), PowerPoint(pptx), 한글(hwpx), OpenDocument. PDF와 예전 hwp·doc·xls 형식은 아직 읽지 못합니다.

### 수백만 개 파일에서 내용을 어떻게 다루나

모든 파일의 내용을 색인하는 것은 디스크와 시간이 너무 많이 들고, 대부분은 쓸 일이 없습니다. 그래서 두 가지를 섞었습니다.

1. **내용 색인 (자주 찾는 폴더만)**: 설정 > 내용 색인에서 폴더를 고르면 그 안의 문서에서 글자 두 개 단위(바이그램) 역색인을 만들어 디스크에 세그먼트 파일로 저장합니다. 메모리에는 작은 견본만 올리고, 문서 원문은 저장하지 않습니다. 검색할 때 색인으로 후보 파일을 몇 개로 줄인 뒤 그 파일만 다시 읽어 정확히 확인하므로, 수십만 개 문서가 있어도 몇 초 안에 끝납니다. 바뀐 파일은 실시간 감시(관리자 모드)나 30분마다 훑기로 그 파일만 다시 색인합니다.
2. **즉석 검색 (색인 안 한 곳)**: 색인하지 않은 파일은 검색할 때 여러 개를 동시에 직접 읽습니다. 진행률이 보이고 언제든 **중지**할 수 있으며, 찾을 파일이 3만 개를 넘으면 범위를 좁히라고 먼저 알려 줍니다. "내용 색인된 폴더만"을 켜면 색인된 파일만 봅니다.

### 규모 (측정치)

- 이름 색인은 이름을 하나의 큰 바이트 배열에 몰아 담아 항목당 약 100바이트를 씁니다. 합성 500만 항목에서 메모리 약 470MB, 검색 28~120ms.
- GitHub Actions의 Windows 머신(약 134만 항목)에서 MFT 첫 색인 37.6초. 이후 실행은 디스크 캐시를 불러오고 그 사이 바뀐 것만 USN 저널로 따라잡습니다.
- 네트워크 폴더와 추가 폴더는 각각 따로 색인하고 따로 저장합니다.

## 동작 원리

Microsoft가 공개 문서로 제공하는 Windows API와 일반적인 검색 기법만 썼습니다.

1. **MFT 직접 읽기**: `FSCTL_ENUM_USN_DATA`로 NTFS 드라이브의 모든 파일 레코드(파일 ID, 부모 ID, 이름)를 한 번에 읽습니다. 관리자 권한이 없거나 NTFS가 아니면 폴더 탐색으로 자동 전환합니다.
2. **이름만 메모리에 보관**: 항목마다 이름과 부모 위치만 저장하고 전체 경로는 필요할 때 조립합니다. 이름순으로 정렬해 두어 결과를 따로 정렬할 필요가 없고, 여러 코어로 나눠 검색합니다.
3. **USN 저널로 실시간 반영**: `FSCTL_READ_USN_JOURNAL`로 생성·삭제·이름 변경·수정을 읽어 작은 오버레이에 반영하고, 쌓이면 다시 합칩니다.
4. **크기·날짜**: 폴더 탐색은 훑을 때 함께 읽고, MFT 모드는 뒤에서 채웁니다.
5. **화면**: exe 안에 든 웹 화면을 `127.0.0.1`에서만 띄우고, 실행마다 바뀌는 토큰이 있어야 응답합니다.

빌드: `cd go && GOOS=windows go build -ldflags "-H windowsgui -s -w" -o ../REASearch.exe .` (콘솔에서 `-selftest`를 보려면 `-H windowsgui` 없이 빌드)

## Python 프로토타입 (참고용)

처음 만든 Python 버전입니다. 이름 검색만 있습니다.



```bat
:: Windows: GUI (관리자 권한으로 실행하면 NTFS MFT를 직접 읽어 수 초 안에 색인)
python -m rea_search
run_gui.bat            :: 같은 동작, 우클릭 > 관리자 권한으로 실행

:: CLI
python -m rea_search cli                       :: 대화형 검색
python -m rea_search cli 보고서 ext:pdf;docx   :: 한 번만 검색
python -m rea_search cli --root D:\Projects    :: 특정 폴더만 색인
python -m rea_search cli --rebuild             :: 캐시 무시하고 다시 색인
```

GUI에서 더블클릭/Enter는 열기, 우클릭은 열기·폴더 열기·전체 경로 복사입니다.

## REA는 어디에 쓰나

영상에서 소개된 REA(**Reverse-Engineer Anything**, https://github.com/morluto/rea)는 Claude Code 같은 코딩 에이전트에 붙이는 리버스 엔지니어링 MCP 서버입니다. 에이전트가 Ghidra/IDA/Hopper 등을 통해 프로그램을 분석하고, 근거와 함께 동작을 설명해 주면 그걸 바탕으로 비슷한 기능을 구현하는 흐름입니다.

이 프로젝트는 다른 제품의 코드, 리소스, UI, 상표를 복사하지 않고 처음부터 직접 작성한 구현입니다. 사용한 것은 Microsoft가 공개 문서로 제공하는 Windows API(`FSCTL_ENUM_USN_DATA`, `FSCTL_READ_USN_JOURNAL`)와 일반적인 검색 기법뿐입니다. 다른 상용 프로그램의 바이너리를 REA로 분석하는 작업은 하지 않습니다.

REA는 이 프로젝트 자신의 코드를 분석·개선할 때 쓸 수 있습니다:

```bat
npx rea-agents setup          :: Claude Code 등에 REA MCP 등록 (Node.js 22+ 필요)
```
