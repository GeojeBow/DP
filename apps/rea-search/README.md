# REA Search

파일 이름을 입력하는 즉시 찾아 주는 Windows용 검색 프로그램입니다. 필요할 때는 파일 **내용**에서 단어를 찾을 수도 있습니다.

## 실행

1. `REASearch.exe`를 내려받아 더블클릭합니다. 설치나 Python은 필요 없습니다.
2. REA Search 전용 창이 열리고 작업 표시줄에도 REA Search 아이콘으로 나옵니다. 콘솔 창은 없습니다. 창은 Windows 10/11에 기본으로 들어 있는 WebView2(Edge 엔진)로 그립니다. WebView2가 없는 PC에서는 Edge나 Chrome의 앱 창으로 대신 엽니다.
3. 창을 닫아도 프로그램은 뒤에서 색인을 최신으로 유지합니다. exe를 다시 실행하면 즉시 창만 다시 열립니다. 완전히 끄려면 **설정 > 정보 > 프로그램 완전히 종료**를 누릅니다.

아무것도 설치하지 않고, 기본으로는 관리자 권한도 요청하지 않습니다(회사 PC의 보안 창이 뜨지 않음). 이때는 폴더를 훑어서 색인하고 한 시간마다(설정 > 색인 일정에서 변경) 다시 훑습니다. 내 PC처럼 관리자 권한을 쓸 수 있으면 **설정 > 단축키·시작·권한 > 빠른 색인**을 켜 두세요. NTFS 드라이브 전체를 몇십 초 안에 색인하고 이후 변경을 실시간으로 반영합니다. 관리자 권한은 이 파일 목록을 읽는 데만 씁니다.

서명되지 않은 새 프로그램이라 Windows SmartScreen이 경고를 띄울 수 있습니다. **추가 정보 > 실행**을 누르면 됩니다.

옵션: `REASearch.exe D:\Projects` (이 폴더만 색인), `-no-admin` (설정과 관계없이 관리자 권한 요청 안 함), `-port 39713` (화면 포트).
데이터 폴더: `%LOCALAPPDATA%\REASearch` (색인 캐시, 설정, `REASearch.log`).

## 화면과 기능

- **이름 검색**: 입력하는 즉시 결과. `Aa` 대소문자 구분, `경로` 전체 경로에서 찾기, `.*` 정규식.
- **결과 안에서 좁히기** (결과 바로 위 필터 줄): 검색한 뒤 결과가 많을 때 마우스로 좁힙니다. 검색창의 검색어는 그대로 둡니다.
  - **결과 내 검색**: 지금 결과 안에서 다시 찾습니다. 여러 단어는 모두 들어간 것, `!초안`은 뺀 것, `\`가 들어간 단어(`영업팀\`)는 경로에서 찾습니다.
  - **유형 / 확장자 / 폴더 / 수정한 날짜 / 크기** 버튼: 누르면 목록이 열리고 항목마다 지금 결과에서 몇 개인지 나옵니다. 유형과 확장자는 여러 개를 체크할 수 있고, 마우스를 올리면 나오는 **이것만**으로 하나만 고릅니다. 폴더는 누를 때마다 하위 폴더로 들어가고, 날짜·크기는 직접 지정도 됩니다. 켜진 필터는 파란 버튼으로 보이고 ✕로 그것만 풉니다.
  - **열 머리글의 깔때기**: 엑셀처럼 이름·경로·크기·수정한 날짜·유형 머리글에 마우스를 올리면 깔때기가 나오고, 누르면 그 열의 필터가 열립니다. 머리글 글자를 누르면 정렬입니다.
  - **요약 줄**: 결과 개수와 합계 크기, 유형 비율 막대(색을 누르면 그 유형만), 그리고 "'영업팀' 폴더만 120개", ".xlsx만 80개", "최근 7일에 바뀐 것 12개" 같은 **추천** 버튼을 보여 줍니다.
  - **묶어 보기**: 폴더별, 유형별, 확장자별, 수정한 날짜별, 크기별로 묶습니다. 묶음 제목을 누르면 접고 펼치고, 제목 옆 "이 묶음만 보기", "이 묶음 모두 선택"을 쓸 수 있습니다.
  - **← →** 버튼(`Alt+←`, `Alt+→`): 필터를 바꾸기 전 상태로 되돌리고 다시 갑니다. **필터 모두 해제**로 한 번에 풉니다.
  - 왼쪽 "결과가 있는 폴더"와 결과 위 **위치** 줄(전체 › C: › 업무 › 2024)로도 폴더를 오르내립니다. 결과를 우클릭해 "결과에서 이 폴더만 보기", "결과에서 .hwp만 보기"도 됩니다.
- **여러 파일 골라서 다루기**: 줄 왼쪽 체크 칸(또는 `Ctrl`·`Shift`+클릭, `Ctrl+A`)으로 고르면 목록 아래에 작업 줄이 나옵니다. 열기, 폴더에서 보기, 경로 복사, **복사…**, **이동…**(폴더를 고르거나 최근에 쓴 위치), **이름 바꾸기**(`F2`), **휴지통**(`Delete`, 확인 후 휴지통으로 보내므로 되살릴 수 있음). 복사·이동·휴지통은 Windows 탐색기와 같은 방식으로 처리되어 진행 창, 같은 이름 확인, `Ctrl+Z` 되돌리기가 그대로 됩니다. 불러온 것보다 결과가 많으면 "결과 전체 선택"(최대 1만 개)이 나옵니다.
- **보기**: 검색 결과, 중복 파일 찾기, 폴더 용량(안에 든 파일 크기 합계가 큰 폴더 순), 최근 바뀐 파일(실시간 감시로 들어온 생성·수정·이름 변경·삭제).
- **중복 파일 찾기**: "이름·크기가 같은" 파일을 바로 묶어 보여 주고, "내용까지 같은"을 고르면 이름이 달라도 내용이 같은 파일을 찾습니다. 크기가 같은 파일끼리만 앞뒤 64KB를 먼저 비교하고, 그래도 같은 것만 전체를 비교(SHA-256)하므로 빠릅니다.
- **정렬**: 열 머리글 글자를 클릭(이름, 경로, 크기, 날짜, 유형). 한 번 더 누르면 반대 순서입니다.
- **미리보기**: 텍스트는 앞부분과 일치한 줄, 이미지는 그림, 폴더는 들어 있는 항목.
- **저장한 검색, 최근 검색**, 결과 **CSV 내보내기**(Excel에서 한글이 깨지지 않게 저장).
- **우클릭 메뉴**: 열기, 폴더에서 보기, 경로·이름 복사, 결과에서 이 폴더만 보기, 결과에서 이 확장자만 보기, 이 폴더 내용 검색, 내용 색인에 추가, 복사…, 이동…, 이름 바꾸기, 휴지통으로 보내기.
- **추가 폴더**(설정 > 검색할 폴더): 네트워크 공유(`\\서버\공유`)나 다른 드라이브를 추가합니다. 폴더마다 다시 훑는 간격(기본 1시간)을 정하고, 연결이 끊겨도 마지막 색인을 유지합니다.
- **어디서든 부르기**: 다른 프로그램을 쓰다가 `Ctrl+Alt+F`(설정 > 단축키·시작·권한에서 변경)를 누르면 검색 창이 앞으로 나오고 바로 입력할 수 있습니다.
- **Windows 시작 시 실행**: 설정 > 단축키·시작·권한에서 켜면 로그인할 때 창 없이 시작합니다. 관리자 권한으로 켜면 작업 스케줄러에 등록되어 매번 권한 확인 창 없이 빠른 NTFS 방식으로 시작합니다.
- **색인 일정**(설정 > 색인 일정): 이름 색인(드라이브), 추가 폴더마다, 내용 색인마다 **주기**(15분~일주일, 또는 사용 안 함)와 **매일 정한 시각**(예: 09:00, 18:30, 여러 개 가능)을 언제든 바꿀 수 있습니다. 바꾸면 바로 저장·적용되고, 마지막 실행과 다음 실행 시각이 보이며 "지금 색인"으로 바로 돌릴 수도 있습니다. 둘 다 끄면 직접 누를 때만 색인합니다. NTFS 실시간 방식에서는 바뀐 파일이 즉시 반영되므로 주기는 쓰지 않고, 정한 시각에만 처음부터 다시 색인합니다.
- **색인 현황**(위쪽 버튼): 이름 색인 방식과 드라이브별 항목 수, 마지막 색인·저장 시각, 열 수 없어 건너뛴 폴더, 추가 폴더별 연결 상태와 다음 탐색 시각, 내용 색인 현황과 읽지 못한 파일 목록(이유별: 암호 문서, 글자 없는 PDF, 손상 등), 메모리 사용량. "이름 색인 처음부터 다시 만들기" 버튼도 있습니다. 경고나 오류가 생기면 버튼에 숫자가 뜹니다.
- **로그**: 무엇을 언제 했고 무엇이 실패했는지 시간순으로 보여 줍니다. "경고·오류만" 보기, 복사(문제를 알릴 때 붙여 넣기), 로그 파일 위치 열기. 로그는 `%LOCALAPPDATA%\REASearch\REASearch.log`에 남고 직전 실행의 로그는 `REASearch.old.log`로 보관됩니다.
- **사용설명서**: 위쪽 `?` 버튼이나 `F1`을 누르면 이 설명서를 프로그램 안에서 볼 수 있습니다. 목차로 이동하고 위쪽 칸에서 단어를 찾을 수 있습니다.
- 단축키: `F1` 사용설명서, `Ctrl+F` 이름 검색, `Ctrl+Shift+F` 내용 검색, `Enter` 열기, `Ctrl+Enter` 폴더에서 보기, `Space` 미리보기, `Ctrl+C` 경로 복사, `Ctrl+A` 모두 선택, `F2` 이름 바꾸기, `Delete` 휴지통, `Alt+←/→` 필터 되돌리기, `Esc` 선택 해제.

## 이름 검색 문법

| 입력 | 의미 |
|---|---|
| `foo bar` | 이름에 foo **와** bar가 모두 포함 |
| `foo \| bar` | foo **또는** bar |
| `!foo` | foo 제외 |
| `*.mp4`, `d?g.*` | 와일드카드 (이름 전체와 일치) |
| `json\ decoder` | `\`나 `/`가 들어간 단어는 전체 경로에서 찾기 |
| `ext:jpg;png` | 확장자 필터 |
| `file:` / `folder:` | 파일만 / 폴더만 |
| `"two words"` | 공백 포함 단어 |
| `size:>100mb`, `size:1mb..10mb`, `size:0` | 크기 (b, kb, mb, gb) |
| `dm:today`, `dm:7d`, `dm:2024`, `dm:2024-03` | 수정한 날짜 (오늘, 최근 7일, 연도, 월) |
| `dm:>2024-01-01`, `dm:2024-01-01..2024-03-31` | 날짜 이후, 기간 |

## 파일 내용 검색 (원할 때만)

### 검색창 하나로: 이름 / 이름+내용 / 내용

검색창 옆의 **이름 · 이름+내용 · 내용** 중에서 고릅니다(마지막 선택을 기억합니다).

- **이름**: 평소처럼 파일 이름만 찾습니다.
- **내용**: 검색창에 쓴 조건을 **내용에** 담고 있는 모든 문서를 찾습니다. 결과마다 일치한 줄이 나옵니다.
- **이름+내용**: 이름이 맞거나 내용이 맞는 파일을 함께 보여 줍니다.

검색창 안에서 `ext:`, `size:`, `dm:`, `path:`, `folder:`, 경로(`D:\업무\`)는 **찾을 범위**로, 나머지 단어는 **내용 조건**으로 나뉩니다. 예: `예산 !초안 ext:hwp;xlsx dm:2024` 는 "2024년에 고친 hwp·xlsx 중 '예산'은 있고 '초안'은 없는 문서", `"분기 실적" | 회의록 D:\업무\` 는 "D:\업무 안에서 구문 '분기 실적'이나 '회의록'이 들어 있는 문서"입니다. 위쪽 필터 줄과 `Aa`·`.*` 옵션도 그대로 범위로 적용됩니다.

내용 모드에서는 문서 파일(텍스트·오피스·한글·PDF 등)만 읽고, "시스템·프로그램 폴더 제외"(기본 켜짐)로 Windows, Program Files, AppData 등은 건너뜁니다. 내용 색인된 폴더는 바로 찾고, 색인 안 된 문서가 3만 개를 넘으면 색인된 곳 결과부터 보여 준 뒤 **"색인 안 된 문서 N개도 읽기"** 버튼으로 나머지를 읽을 수 있습니다. 자주 찾는 폴더는 설정 > 내용 색인에 넣어 두면 항상 즉시 나옵니다.

### 찾은 파일 안에서 찾기

위쪽 **내용 검색** 버튼(`Ctrl+Shift+F`)을 누르면 내용 검색 줄이 열립니다. 찾을 범위는 **지금 이름 검색과 필터에 걸린 파일**입니다. 예를 들어 이름 칸에 `ext:docx;hwpx`, 날짜 필터 "최근 30일"을 걸고 내용 칸에 단어를 넣으면 그 파일들만 읽습니다.

| 입력 | 의미 |
|---|---|
| `회의 예산` | 두 단어가 **모두** 있는 파일 (AND) |
| `회의 \| 예산` 또는 `회의 OR 예산` | 둘 중 **하나**라도 (OR) |
| `회의 !취소` 또는 `회의 -취소` | 회의는 있고 취소는 **없는** 파일 (NOT) |
| `"분기 실적"` | 정확히 이 구문 |

옵션: `Aa` 대소문자 구분, `단어` 단어 단위로만 일치, `.*` 정규식. 결과마다 일치한 줄이 강조되어 나오고, 미리보기에서 전체 일치 줄을 볼 수 있습니다.

읽는 형식: 텍스트·코드 파일(UTF-8, UTF-16, EUC-KR/CP949), 한글(hwp, hwpx), Word(doc, docx), Excel(xls, xlsx), PowerPoint(ppt, pptx), PDF, OpenDocument. 예전 hwp·doc·xls·ppt는 공개된 파일 형식 문서(한컴 HWP 5.0 문서, Microsoft의 MS-CFB·MS-DOC·MS-XLS·MS-PPT)를 보고 직접 구현했고, PDF는 ISO 32000 명세를 보고 직접 구현했습니다. 암호가 걸린 문서, 배포용 한글 문서, 스캔한 이미지뿐인 PDF는 읽지 못하며 색인 현황에서 목록으로 확인할 수 있습니다. 손상된 파일은 건너뛰고 기록만 남깁니다.

### 수백만 개 파일에서 내용을 어떻게 다루나

모든 파일의 내용을 색인하는 것은 디스크와 시간이 너무 많이 들고, 대부분은 쓸 일이 없습니다. 그래서 두 가지를 섞었습니다.

1. **내용 색인 (자주 찾는 폴더만)**: 설정 > 내용 색인에서 폴더를 고르면 그 안의 문서에서 글자 두 개 단위(바이그램) 역색인을 만들어 디스크에 세그먼트 파일로 저장합니다. 메모리에는 작은 견본만 올리고, 문서 원문은 저장하지 않습니다. 검색할 때 색인으로 후보 파일을 몇 개로 줄인 뒤 그 파일만 다시 읽어 정확히 확인하므로, 수십만 개 문서가 있어도 몇 초 안에 끝납니다. 바뀐 파일은 실시간 감시(관리자 모드)나 정해 둔 일정(기본 30분마다)에 훑어 그 파일만 다시 색인합니다.
2. **즉석 검색 (색인 안 한 곳)**: 색인하지 않은 파일은 검색할 때 여러 개를 동시에 직접 읽습니다. 진행률이 보이고 언제든 **중지**할 수 있으며, 찾을 파일이 3만 개를 넘으면 범위를 좁히라고 먼저 알려 줍니다. "내용 색인된 폴더만"을 켜면 색인된 파일만 봅니다.

### 규모 (측정치)

- 이름 색인은 이름을 하나의 큰 바이트 배열에 몰아 담아 항목당 약 100바이트를 씁니다. 합성 500만 항목에서 메모리 약 470MB, 검색 28~120ms.
- GitHub Actions의 Windows 머신(약 134만 항목)에서 MFT 첫 색인 37.6초. 이후 실행은 디스크 캐시를 불러오고 그 사이 바뀐 것만 USN 저널로 따라잡습니다.
- 네트워크 폴더와 추가 폴더는 각각 따로 색인하고 따로 저장합니다.

## 동작 원리

Microsoft가 공개 문서로 제공하는 Windows API와 일반적인 검색 기법만 썼습니다.

1. **MFT 직접 읽기**: `FSCTL_ENUM_USN_DATA`로 NTFS 드라이브의 모든 파일 레코드(파일 ID, 부모 ID, 이름)를 한 번에 읽습니다. 관리자 권한이 없거나 NTFS가 아니면 폴더 탐색으로 자동 전환합니다.
2. **이름만 메모리에 보관**: 항목마다 이름과 부모 위치만 저장하고 전체 경로는 필요할 때 조립합니다. 이름순으로 정렬해 두어 결과를 따로 정렬할 필요가 없고, 여러 코어로 나눠 검색합니다.
3. **USN 저널로 실시간 반영**: `FSCTL_READ_USN_JOURNAL`로 생성·삭제·이름 변경·수정을 읽어 작은 오버레이에 반영하고, 쌓이면 다시 합칩니다.
4. **크기·날짜**: 폴더 탐색은 훑을 때 함께 읽고, MFT 모드는 뒤에서 채웁니다.
5. **화면**: exe 안에 든 웹 화면을 `127.0.0.1`에서만 띄우고, 실행마다 바뀌는 토큰이 있어야 응답합니다. 이 화면을 Windows의 WebView2로 프로그램 자체 창에 그립니다(아이콘·작업 표시줄 표시가 REA Search로 나옴).
6. **파일 작업**: 복사·이동·휴지통은 Windows의 `SHFileOperation`(탐색기와 같은 진행 창과 되돌리기), 폴더 고르기는 Windows 기본 폴더 선택 창(`IFileOpenDialog`)을 씁니다.

## Python 프로토타입 (참고용)

처음 만든 Python 버전입니다. 이름 검색만 있습니다.



```bat
:: Windows: GUI (관리자 권한으로 실행하면 NTFS MFT를 직접 읽어 수 초 안에 색인)
python -m rea_search
run_gui.bat            :: 같은 동작, 우클릭 > 관리자 권한으로 실행

:: CLI
python -m rea_search cli                       :: 대화형 검색
python -m rea_search cli 보고서 ext:pdf;docx   :: 한 번만 검색
python -m rea_search cli --root D:\Projects    :: 특정 폴더만 색인
python -m rea_search cli --rebuild             :: 캐시 무시하고 다시 색인
```

GUI에서 더블클릭/Enter는 열기, 우클릭은 열기·폴더 열기·전체 경로 복사입니다.

## REA는 어디에 쓰나

영상에서 소개된 REA(**Reverse-Engineer Anything**, https://github.com/morluto/rea)는 Claude Code 같은 코딩 에이전트에 붙이는 리버스 엔지니어링 MCP 서버입니다. 에이전트가 Ghidra/IDA/Hopper 등을 통해 프로그램을 분석하고, 근거와 함께 동작을 설명해 주면 그걸 바탕으로 비슷한 기능을 구현하는 흐름입니다.

이 프로젝트는 다른 제품의 코드, 리소스, UI, 상표를 복사하지 않고 처음부터 직접 작성한 구현입니다. 사용한 것은 Microsoft가 공개 문서로 제공하는 Windows API(`FSCTL_ENUM_USN_DATA`, `FSCTL_READ_USN_JOURNAL`)와 일반적인 검색 기법뿐입니다. 다른 상용 프로그램의 바이너리를 REA로 분석하는 작업은 하지 않습니다.

REA는 이 프로젝트 자신의 코드를 분석·개선할 때 쓸 수 있습니다:

```bat
npx rea-agents setup          :: Claude Code 등에 REA MCP 등록 (Node.js 22+ 필요)
```
